# 实现总结（给人看的版本）

> 读者对象：新加入的同事、技术评审、想快速理解"这个系统到底怎么做的"的任何人。
> 与其他文档的关系：`system_overview.md` 讲分层，`roadmap.md` 讲阶段史，
> 29 个 `requirements/stage-*` 讲单点需求——**本文横向讲每个能力的实现思路与
> 关键取舍**，每节末尾给代码与文档指针。截至 2026-08-05（Stage 29）。

---

## 0. 一句话架构

FastAPI + LangGraph 的**规则优先、模型辅助、LLM 兜底**客服对话系统：
14 个节点的决策图，每轮产出完整决策证据落 PostgreSQL；写操作永远经确认门；
所有 LLM 依赖可降级（无 Key 全链路离线可跑）；前端 Vue 控制台覆盖全部接口。

```text
用户消息 → 会话加载 → 预处理 → 护栏 → 意图识别 → 槽位抽取 → 确认门解析
        → 状态机流转 → 技能路由 ─┬─ 模板回复（补槽/确认/澄清）
                                ├─ RAG 知识问答      ├─ 商品库直答
                                ├─ 工具查询（mock/MCP）└─ 写操作执行（确认门后）
        → 落库（消息/决策日志/任务/审计）
```

## 1. 意图识别（本系统最厚的一层，做重点展开）

**核心认知：意图识别不是一个分类器，是一条判定流水线。** 单模型分类解决不了
「是的」在确认门下是确认、在闲聊里是废话这类上下文问题，所以拆成四层，
**顺序即优先级，前层命中即短路**：

```text
第 1 层 规则控制层（确定性，零模型）        app/chat/intent/rule_classifier.py
  ├─ 取消订单正则（先于裸「取消」，被动式「订单被取消了」排除）
  ├─ 确认门应答（仅 CONFIRMING 状态判定；≤10 字防吞带新诉求长句）
  ├─ 任务中途否定（仅 COLLECTING；「不是要退货」→终止当前任务不清栈）
  ├─ 转人工/身份询问/纯放弃（残差判定：去掉放弃词后只剩语气词才算）
  ├─ 纯槽位输入（裸订单号/手机号 → 直接续接当前任务）
  └─ 补槽守护（COLLECTING 下「订单号是12345678」定向提取：
      证据分级 + 四条防误填规则，不进语义层——防止被误判成新意图）

第 2 层 SetFit 语义层（本地小模型，CPU ~15ms）  setfit_classifier.py
  29 类业务意图；输出 top_k + 置信度 + margin(top1-top2)；
  写意图更高采纳线（0.60 vs 0.40）——错开高风险流程的代价大于多问一句

第 2.5 层 margin 路由 + 示例近邻交叉验证        hybrid_classifier.py + example_knn.py
  高分但 margin<0.10 = 分类头拿不准 → 先查训练集近邻（SetFit 同源向量）：
  近邻同意 top1 → 免二判直接采纳；不同意 → 绝不改选，证据落库走第 3 层

第 3 层 LLM 难例二判（成本只花在难例上）        llm 二判 prompt
  只在候选目录内裁决（输出不在目录 = 失败），不开放式猜意图

第 4 层 兜底 META.UNKNOWN → 智能澄清（LLM 生成针对性问句，无 Key 用模板）
```

分类之后还有三道**决策防线**（Stage 23/26）：

- **软确认**：中置信新开任务，追问话术前复述意图（「您是想退货对吗？」），
  不阻塞流程，用户扫一眼即可纠偏；
- **切换守护**：补槽/确认门中冒出新意图，须高置信+margin 达标或显式切换信号
  （「另外/顺便」）才挂起切换，否则二选一澄清——误切吞掉任务上下文的代价
  （×5）远大于多问一句（×1）；
- **UNKNOWN 续接收紧**：有任务时未知消息不整包吞槽位（防「我有12345678个
  问题」的数字串污染订单号），无续接证据则保持任务并澄清。

一个真实轮次的判定轨迹（决策日志可回放）：

```text
状态：退款任务 COLLECTING 等 order_id；用户：「订单号是12345678」
第 1 层控制层 → 补槽守护命中（evidence=explicit_slot_name）
→ META.SLOT_ONLY / RULE_PENDING_SLOT → 状态机续接退款任务
→ 槽位齐 → 写操作进确认门 NEEDS_CONFIRM
（SetFit 根本没跑——这句话在 Stage 26 之前会被误判成"订单查询"开新任务）
```

**多意图**：并列标记分段 + 每段独立分类抽槽（防串槽），次要意图入任务栈
主任务结束自动续办。**演进方向已铺好**：决策日志攒真实特征 → Meta-classifier
（已训练管线+影子模式在线对照）学习"续接/切换/二判/澄清"决策，替代手调阈值。

指针：`app/chat/intent/`、`docs/chat/intent_taxonomy.md`（单一事实来源）、
stage-04/23/26/27 需求文档、`docs/intent/meta_classifier_training.md`。

## 2. 对话状态机与任务治理

纯决策类（不碰 DB 不调 LLM）：`当前状态 + 任务 + 栈 + 意图 + 槽位 → 流转`。
关键机制：任务栈（打断挂起 LIFO 恢复 + 槽位继承）、追问上限放弃、TTL 过期
不复活、零进度恢复降调、节点写契约（每个图节点只能写声明过的字段，
越权测试即红——学 Dify 变量纪律）。
指针：`app/chat/state/manager.py`、`app/chat/graph/contracts.py`、stage-03/05/10。

## 3. 写操作：确认门 + 唯一写入口

红线：**LLM 永远不直接执行写操作**。写意图槽位齐全只进 CONFIRMING；
确认后由 ActionExecutor（唯一写入口）执行：条件 UPDATE 原子拿执行权
（并发确认恰好执行一次）、三重校验、独立事务 EXECUTING 标记、工单号回执、
全程 chat_tool_call 审计。含糊应答（「嗯」「好的」）走 LLM 解析 +
L3 弱确认收紧（要求明说「确认」）。
指针：`app/chat/actions/`、`app/chat/confirmation/`、stage-05/13。

## 4. 工具层：注册表 + MCP，模型无自由选择权

ToolProvider 协议：mock（确定性假数据）/ MCP（标准协议对接真实系统，
失败禁 mock 冒充事实）。工具目录（catalog.py）声明 readonly 标记：
诊断 agent 的只读白名单由声明推导，MCP 工具凭 readOnlyHint 注解自动入列，
**目录声明为写的工具谁标只读都拒绝**。诊断 agent（"为什么还没到"）是
ReAct 受约束变体：只读白名单 + 全部结构性终止 + 数字事实校验。
指针：`app/chat/tools/`、`app/chat/agents/diagnose.py`、stage-11/22、post-stage-27。

## 5. RAG / 知识库

PG 是唯一事实源（Milvus 只是索引，可随时重建）；解析器链（MinerU→Docling→
内置）+ 结构感知切分（标题路径注入/表格独立成块/父子分块）；检索 =
query 归一化（繁简/同义词/型号判型）→ 多路宽召回 → 动态加权 RRF →
可选 CrossEncoder 重排 → 歧义检测；含糊查询 LLM 先改写再检索、引用溯源
到 chunk。**红线：价格/库存禁走 RAG**（商品库唯一事实源）、拒答不编造。
运营侧：草稿-审核-发布状态机 + 版本回滚（生效判据 = published_version
非空且未 archived，不单看 status）。
指针：`app/kb/`、stage-06 系列/16、post-stage-20 RAG 强化。

## 6. 安全：护栏 + 鉴权 + 脱敏

护栏规则库是文档里的机器可读表格（改规则=改表格）：注入拦截、辱骂分级
连击转人工、情绪 flag 软化、5 个 LLM 拼接点统一防注入包裹、输出护栏
（润色违规回退底稿）。鉴权：API Key per tenant（bcrypt + 即时吊销 +
scope 分离 chat/admin）、限流、幂等（在途锁+指纹）。脱敏在落库前完成
（决策日志/审计表原样可外流给分析）。生产硬门禁：APP_ENV=prod 缺项拒绝启动。
指针：`app/chat/guardrail/`、`app/core/auth.py`、stage-08/13/14。

## 7. 记忆与成本

记忆三层：短期窗口 / 结构化会话摘要（固定 schema，「保留具体值禁概括」）/
长期事实表——写入在主事务 after-commit 后异步（rollback 无幽灵记忆）。
成本三件套（默认全关零回归）：语义缓存（事实类永不缓存）、租户 token
日预算熔断（超限走模板）、模型分级路由（分类走小模型生成走大模型）。
A/B 实验：确定性 hash 分桶 + 白名单参数注入，决策日志落变体。
指针：`app/chat/memory/`、`app/chat/cache/`、`app/experiments/`、stage-10/17/18/20。

## 8. 可观测与数据飞轮

每轮一行决策日志（意图证据/margin/补槽证据/护栏结论/检索轨迹/实验变体/
Meta 影子预测/耗时），支撑：决策回放、质量看板（quality_daily）、
**两条训练回路**——意图分类器（低置信/差评轮次导出→人工改标→重训）与
Meta-classifier（影子特征采集→hindsight 信号定审核优先级→改标→重训）。
Prometheus 指标 + Grafana 看板 + 告警规则 + Langfuse 链路明细。
指针：`app/core/metrics.py`、`scripts/export_*.py`、stage-09/12/25/27。

## 9. 前端控制台（Vue 3 + Element Plus）

登录（API Key 模型，无独立账号体系）→ 左侧多级菜单：对话控制台
（决策标签+SSE 流式+WS 推送+反馈）、观测分析（会话记录+逐轮决策日志
页面化）、坐席工作台（双端 WS 实时闭环）、知识库运营（状态机全操作）、
商品库、系统状态。32 个后端接口全部页面可用。
指针：`web/`、stage-28/29、`docs/ops/web_console_deploy.md`。

## 10. 贯穿全局的工程纪律（比单个功能更值得看）

1. **单一事实来源**：意图码在 taxonomy、护栏规则在表格、工具声明在 catalog、
   特征契约在训练脚本常量——改规则先改声明处，代码从声明推导；
2. **一切可降级**：无 LLM Key/Redis 故障/Milvus 不可达/模型产物缺失，
   全部有确定性回退路径，降级打标不装正常；
3. **决策可回放**：不落证据的决策不允许存在——这也是训练数据的来源；
4. **红线用结构保证而非约定**：确认门在状态机里、白名单 deny-by-default、
   写契约有测试执法、事实类禁缓存禁 RAG；
5. **零回归推进**：每个 Stage 默认关或语义等价，全量测试（455+）必须绿；
6. **文档先行**：需求文档是实施依据，冲突以文档为准。
