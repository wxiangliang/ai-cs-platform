# Stage 39 需求：预约与资源调度（Appointment Booking）

> 客服的终点常常不是「回答问题」而是**协调真实资源**：安装/维修/取件/
> 退货上门/回访/演示。本 Stage 用 mock 资源池把机制链路整条打通
> （MEMBER.REGISTER 同路线：对接真实调度系统只换工具内部）。

---

## 1. 意图与流程（APPOINTMENT 域，第 11 域）

| 意图 | 风险 | 槽位 | 流程 |
|---|---|---|---|
| APPOINTMENT.BOOK | L2 写 | service_type（安装/维修/取件/退货上门/回访/演示，词表抽取）、appointment_time（时间表达正则）、phone | 收集 → **确认门**（复述类型/时间/电话）→ ActionExecutor `create_appointment` → 回执含预约号 |
| APPOINTMENT.CANCEL | L2 写 | appointment_no（AP 前缀号） | 收集 → 确认门 → `cancel_appointment` |

触发：规则层确定性关键词（零重训）——「预约安装/帮我约个维修/上门取件」
→ BOOK；「取消预约」→ CANCEL（**先于 BOOK 判定**，且被动式「预约被取消了」
按状态咨询不触发——cancel-order 正则同款防误伤）。语义层兜底进 LLM 二判
目录。改期 v1 = 取消 + 重约（改期幂等属真实系统契约，遗留 2）。

## 2. 用户提出的七个风险点的处理

| 风险 | v1 处理 |
|---|---|
| 资源并发 | mock 资源池按 (service_type, 时间槽) 容量 3 原子扣减，满 → `SLOT_FULL` 走执行失败分支（转人工兜底）；真实系统侧由调度系统保证，幂等键随写下发（既有契约） |
| 重复预约 | mock 按 (tenant, phone, type, time) 幂等——同键返回同预约号；跨渠道重复由真实系统按幂等键去重 |
| 时区 | v1 沙盒统一北京时间（回执明示「北京时间」）；对接契约：真实系统时间字段一律 ISO8601 带时区（写入 stage-11 对接契约同节，遗留 1） |
| 时间槽过期 | 过去时间 mock 拒绝（`SLOT_EXPIRED`）；「明天/周五」类相对表达由 mock 按当前日归一 |
| 改期幂等 | v1 取消+重约；真实系统 reschedule 接口按幂等键（遗留 2） |
| 未到场 | 真实系统推 `APPOINTMENT_MISSED` 事件 → **Stage 36 事件通道**发改期引导（模板已备） |
| 提醒频控 | 提醒走 Stage 36 事件（`APPOINTMENT_REMINDER`）——幂等/退订/静默时间全部继承，同一提醒只发一次 |

## 3. 复用盘点（本 Stage 零新机制）

- 多轮收集/确认门/唯一写入口/防重放/审计：Stage 05/13 原样；
- 工具目录声明（readonly `query_appointment_slots` 进诊断白名单 +
  IAL1 全部涉个人数据）：post-27/Stage 35 模式；
- 提醒/未到场：Stage 36 事件白名单加两类；
- 旅程：APPOINTMENT.* 为强证据 → PURCHASED（约安装=已购）。

**「查可用时间→用户选择」的会话式浏览记遗留 3**：需要「任务中途调用
工具再继续收集」机制（与验证码同一缺口，第三次出现——真实系统对接时
一并实现）；v1 用户直接给时间，冲突时由执行失败分支引导换时间。

## 4. 验收

1. 「预约明天下午的空调安装，电话 13800138000」→ 一轮收满 → 确认门 →
   回执含预约号（北京时间明示）；
2. 同槽位满员 → 执行失败转人工；同键重复预约 → 同预约号（幂等）；
3. 「取消预约 AP12345678」→ 确认门 → 取消回执；被动式不触发；
4. REMINDER/MISSED 事件经 Stage 36 全红线（幂等/退订/静默）；
5. 目录/注册表/md 双向覆盖测试通过（35 md）；旅程强证据推进。

## 5. 遗留

1. 真实调度系统对接（时区 ISO8601 契约、真实容量、跨渠道幂等）；
2. 改期原子接口（reschedule with 幂等键）；
3. 会话式时间槽浏览（任务中途工具机制，与验证码同缺口）；
4. 提醒的定时产生方（真实系统 Outbox 或 cron 扫描预约表）。
