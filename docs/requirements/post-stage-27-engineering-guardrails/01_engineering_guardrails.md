# Post-Stage 27 工程护栏（Dify 变量纪律对照评审的两个落地项）

## 1. 背景与目标

2026-08-04 对照 Dify 的变量作用域/工具注册设计做了评审，结论：

- 意图识别不学（Dify Question Classifier = 每轮 LLM 分类，等于只有我们的
  第三层且无状态感知/无评估门禁，客服场景我们的分层混合明确更强）；
- 变量分层五原则对照：画像≠会话状态、会话≠任务状态、临时检索不进画像、
  挂起任务恢复条件明确——四条架构上已满足（user_memory / session metadata /
  dialog_state 分表，retrieval 只落 decision_log，TTL/降调/否定通道）；
  **唯独「节点只读写约定字段」缺机制保护**：GraphState 50+ 字段任何节点
  技术上可写任意键，契约全靠注释自觉（Stage 26 UNKNOWN 整包 merge 污染
  order_id 即此类腐化的实例）；
- 工具注册哲学已对（写操作模型永远无选择权、读工具白名单+结构性终止），
  但诊断 agent 的 READONLY_TOOLS 是硬编码，MCP 新增只读工具需手动同步
  （Stage 22 遗留）。

本次落两个小改动，**零行为变更、零 migration、不需要任何模型重训**：

```text
① 节点写契约表 + 执法：按现状如实登记 14 个节点的写入字段（AST 审计产出），
   图构建时包装节点——越权写在 dev/test 环境直接抛错、prod 只告警
   （契约保护开发过程，不能变成线上故障源）；现有全量链路测试即执法语料；
② 只读工具白名单改元数据推导：deny-by-default 不变，白名单来源从硬编码
   列表改为工具声明的 readonly 标记，MCP 工具用协议标准 readOnlyHint
   注解——注册即生效，生效范围由声明控制而非模型自由度。
```

## 2. 不做什么

```text
1. 不重构 GraphState 为命名空间（大手术零行为收益）；
2. 不改变量分层其余四条的现有实现；
3. 不放开写工具的模型选择权（确认门/ActionExecutor 唯一写入口不动）；
4. 读契约不做（返回键可查，读取无法低成本拦截——记录为已知边界）。
```

## 3. 验收

1. 契约表与 builder 注册节点一一对应（静态测试锁定），契约字段全部存在于
   GraphState 声明（防幽灵字段）；
2. 越权写在非 prod 环境抛 GraphContractViolation，prod 告警放行；
3. 白名单推导后与现行 READONLY_TOOLS 集合一致（零行为变更），未标记
   readonly 的工具（含写工具）永远进不了白名单；
4. 全量测试零回归。

## 4. 遗留

1. 读契约（节点声明读哪些字段）——等有低成本拦截手段再议；
2. MCP readOnlyHint 在真实第三方 MCP 服务上的可信度评估
   （声明可被服务端伪造，接入外部 MCP 时白名单需二次人工确认）。
