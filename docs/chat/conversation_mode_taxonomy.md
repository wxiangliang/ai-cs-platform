# 对话模式体系规范（Conversation Mode Taxonomy）

> **对话模式的单一事实来源**（Stage 30）。改模式语义先改本文档。
> 与 `intent_taxonomy.md` 的分工：意图 taxonomy 回答「用户具体想做什么」
> （业务轴），本文档回答「本轮话语属于哪种交互模式」（模式轴）——
> **模式不是意图**，五个模式码永远不进意图 taxonomy，Meta-classifier
> 六类决策也不加 CHITCHAT（双轴纪律，stage-30 需求第 2 节）。
> 训练操作见 `docs/intent/mode_gate_training.md`。

## 1. 模式定义

| 模式 | 性质 | 定义 | 例子 |
|---|---|---|---|
| SOCIAL_ONLY | 训练标签 | 纯闲聊/社交互动，无业务对象、无域外任务 | 「你回复得还挺快哈哈」「今天心情不错」 |
| TASK_ONLY | 训练标签 | 纯业务或服务控制请求 | 「帮我查订单」「别发货了我不要了」 |
| MIXED | 训练标签 | 社交子句 + 业务子句共存 | 「今天真倒霉，物流怎么还没到」 |
| OOS | 训练标签 | **有明确任务但超出客服业务范围** | 「帮我写一段 Python」「推荐几本理财的书」 |
| UNCERTAIN | **推理拒识结果** | 分数/margin 不达标时的运行时状态。**不是训练标签**——训成类别会让模型把边界难例学成语义杂物桶 | — |

## 2. 三条裁决原则

1. **OOS ≠ 闲聊**：「不属于业务意图」不等于闲聊。闲聊是社交（今天好热/
   谢谢你/哈哈哈），OOS 是用户有明确任务但系统不支持（写代码/股票分析/
   餐厅推荐）。边界对照：「今天天气不错」= SOCIAL_ONLY（寒暄），
   「明天天气怎么样」= OOS（信息查询任务）；
2. **业务信号优先于闲聊信号**：句中出现强业务词/槽位值形态/切换信号时，
   即使模型判 SOCIAL 也不允许直通（「你们退款真的慢死了哈哈」是投诉）。
   礼貌前缀不构成独立社交段（「谢谢，不过我还是想退款」= TASK_ONLY）；
   独立社交子句 + 业务子句才是 MIXED（「你人真好，帮我查查快递」）；
3. **MIXED 业务优先**：混合消息业务动作是主、社交承接是辅——回复先办业务
   （进确认门/补槽），顺带承接社交表达；社交段永远不改任务栈。

## 3. 模式 → 链路动作（v1 接管范围）

| 模式 | 动作 |
|---|---|
| SOCIAL_ONLY 高置信+无反证 | 直通闲聊回复（免二判）；有任务 → SOCIAL_HOLD（保任务+续办提示，**确定性策略非训练标签**，不进 Meta） |
| TASK_ONLY / MIXED / UNCERTAIN | 现有意图流水线原样执行（v1 影子观察，证据落 `intent_result_json.mode_gate`） |
| OOS 高置信 | 子开关开启时回能力边界话术（默认关，影子先行） |

## 4. 变更规范

1. 新增/修改模式语义：先改本文档，再同步 `app/chat/mode/gate.py` 常量、
   训练数据标注指南与 `mode_gate_training.md`；
2. 模式训练数据变更走 `intent_mode_v43_package/` 的生成脚本重建 +
   人工 hard test（`docs/intent/mode_hard_test_v1.csv`）回归；
3. 运行时新增反证词/信号：更新 `_BUSINESS_KEYWORD_RE` 并在
   `tests/stage30` 补对应用例（误吞样本驱动，见训练文档第 4 节闭环）。
