# Stage 32：选品顾问与规则推荐

## 目标

支持从模糊需求到结构化约束，再到 2～4 个可解释商品候选。

## 必须实现

- 动态槽位；
- 最大信息增益式提问规则；
- 商品候选召回接口；
- 硬约束过滤；
- 规则排序；
- trade-off；
- 实时价格库存核验；
- LLM 仅做表达。

## 红线

- 价格库存禁走 RAG；
- 不满足硬约束的商品不得展示；
- 商业权重不得覆盖用户需求；
- 推荐过程完整落证据。

## 验收

- 预算、地区、规格冲突样本全部过滤；
- 推荐理由与结构化事实一致；
- 商品服务故障时不伪造候选；
- 任务切换和恢复不丢已收集需求。
